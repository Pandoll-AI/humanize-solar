# humanize-solar

한국어 원고를 Upstage Solar로 다듬는 Claude Skill. 문장을 쪼개지 않고 어휘와 어순으로 읽기를 개선한다.

## 수정 이력

같은 문서의 코드블록·표·인용·리스트·제목은 **바이트 단위로 그대로다.** 모델에게 보내지도 않는다.

## 왜 이 프롬프트인가

프롬프트는 9라운드에 걸쳐 실측하며 확정했다. 원고 7종(학술·기사·블로그·공지·강의·마케팅·보고문, 각 2,000자)에 조건을 바꿔가며 적용해 보고, 편집량과 원문 손상을 함께 비교했다.

가장 중요한 발견은 **금지어가 오히려 그 행동을 촉발한다**는 점이다.

| 프롬프트 | 지시부 | 변경률 | 무편집 문단 | 문장 분할비 | 곡선따옴표 |
|---|---:|---:|---:|---:|---:|
| 긴 버전 (금지·억제 조항 포함) | 581자 | 2.12% | 15/49 | 1.15배 | 14/22 |
| **짧은 버전 (조항 제거)** | **132자** | **7.66%** | **0/49** | **1.00배** | **22/22** |

"관형절을 끊으면 오히려 읽기 어려워진다", "같은 주어를 문장마다 세우면 글이 통역문처럼 굳는다" 같은 문장을 넣자 오히려 분할이 일어났다. 해당 문장들을 **지우자** 분할비가 1.00배로 돌아왔다. 문장 경계를 하나도 건드리지 않았다는 뜻이다.

곡선따옴표는 더 극적이다. "바꾸지 마라"라고 명시했을 때는 22개 중 14개만 남았고, 아무 말도 하지 않으니 22개 전부가 보존됐다. 한 걸음 더 나아가 "문장부호를 바꾸지 마라"를 조항으로 추가했더니 변경률이 4.34%에서 **0.80%로 붕괴**했다. 조항 하나를 지키게 하려다 편집 자체가 멈춰 선 것이다.

같은 프롬프트를 다른 모델에도 적용해 봤다. 짧은 버전에서는 Solar 7.66%, Qwen 7.02%로 거의 차이가 없었다. 긴 프롬프트에서 2.12% 대 5.57%로 크게 벌어져 보이던 격차는 모델 차이가 아니라 프롬프트 차이였다.

**그러니 이 프롬프트에 조항을 추가하지 말 것.** 무언가를 지키게 하고 싶다면 보호 구역 판정이나 후처리로 다루는 편이 낫다.

## 추론 예산은 편집량을 늘리지 않는다

Solar에는 `reasoning_effort`가 있다. 덜 고치려고 이 값을 올리는 것은 잘못된 처방이다.

| effort | 변경률 | 무편집 문단 | 곡선따옴표 |
|---|---:|---:|---:|
| medium | 2.12% | 15/49 | 14/22 |
| xhigh | 2.20% | 12/49 | **22/22** |

건당 추론 토큰을 4,600~5,800개 더 쓰고 얻은 변경률 차이는 0.08%포인트에 불과하다. 대신 표기 정확도는 올랐다. 곡선따옴표 손실 8개가 전부 복구된 것이다.

**추론을 더 태우면 더 고치는 게 아니라 덜 망가뜨린다.** 편집량과 편집 정확도는 서로 다른 축이다. 기본값 `medium`으로 충분하고, 표기가 자꾸 어긋날 때만 올리면 된다.

## 설치

```bash
git clone https://github.com/pandoll-ai/humanize-solar.git
ln -s "$(pwd)/humanize-solar" ~/.claude/skills/humanize-solar
```

복사해도 된다. Python 3.9 이상이면 되고, **설치할 패키지는 없다.** 표준 라이브러리만 쓴다.

스킬로 쓰지 않고 스크립트만 단독으로 써도 무방하다.

## API 키

[Upstage Console](https://console.upstage.ai/)에서 발급한다.

```bash
export UPSTAGE_API_KEY="up_..."
```

`~/.zshrc`나 `~/.bashrc`에 넣어 두면 편하다.

## 사용법

```bash
python3 scripts/humanize.py 원고.md              # 결과를 화면으로
python3 scripts/humanize.py 원고.md -o 결과.md
cat 원고.md | python3 scripts/humanize.py

python3 scripts/humanize.py 원고.md --effort high
python3 scripts/humanize.py 원고.md --temperature 0.7
python3 scripts/humanize.py 원고.md --dry-run    # 보낼 내용만 확인, 호출 없음
```

결과는 stdout, 진행과 경고는 stderr로 나간다.

| 환경변수 | 기본값 | 설명 |
|---|---|---|
| `UPSTAGE_API_KEY` | (필수) | API 키 |
| `UPSTAGE_BASE_URL` | `https://api.upstage.ai/v1` | 엔드포인트 |
| `HUMANIZE_MODEL` | `solar-pro4` | 모델명 |

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `-o, --output` | stdout | 결과 파일 |
| `--model` | `solar-pro4` | 모델명 (환경변수보다 우선) |
| `--effort` | `medium` | `none` `minimal` `low` `medium` `high` `xhigh` `max` |
| `--temperature` | 0.5 | 표집 온도 |
| `--max-tokens` | 8192 | 응답 상한 |
| `--timeout` | 300 | 초 |
| `--dry-run` | — | 페이로드만 출력하고 종료 |

## 건드리지 않는 것

다음은 그대로 통과한다. 모델에게 보내지도 않는다.

- 코드블록 (` ``` ` 안쪽 전체)
- 제목 (`#`)
- 표 (`|`로 시작하는 줄)
- 인용 (`>`)
- 리스트 항목 (`-`, `*`, `+`, `1.`)
- 빈 줄, 구분선

일반 문단만 윤문한다. 어떤 부분이 대상인지 미리 확인하려면 `--dry-run`을 사용한다.

고유명사·수치·영문 약어·URL은 프롬프트 지침상 변경을 금지한다. 실측 결과 7종 원고 모두 100% 보존됐다.

## 긴 문서

문단을 누적 6,000자 또는 12개 단위로 나누어 전송한다. 한 덩어리가 형식을 어기면 해당 덩어리만 최대 3회 재시도하고, 그래도 실패하면 **원문을 그대로 두고 경고**한다. 나머지 작업은 계속 진행되므로 전체가 중단되지는 않는다.

Solar는 추론 토큰도 함께 소모하므로 effort가 높을수록 응답이 토큰 상한에 걸릴 가능성이 커진다. 잘림 경고가 표시되면 `--max-tokens`를 높이거나 `--effort`를 낮춘다.

## 한계

**변경률은 품질 점수가 아니다.** 많이 고쳐도 나빠질 수 있고, 그대로 둬도 나빠질 수 있다. 이 저장소의 수치는 수정 정도를 나타낼 뿐, 잘 고쳤는지를 평가하지는 않는다. 결과는 사람이 직접 읽고 판단해야 한다.

**실측 표본이 작다.** 스타일당 원고 한 편, 조건당 한 번만 실행했다. 장르 효과와 개별 원고의 효과가 분리되지 않는다. 분할비 1.15 → 1.00처럼 일곱 편 모두 같은 방향으로 나타난 값은 신뢰할 수 있지만, 변경률 7.66% 대 7.02%처럼 미세한 차이는 그렇지 않다.

**재실행하면 결과가 달라진다.** temperature 0.5에서는 같은 원고를 두 번 실행해도 편집 결과가 매번 달라진다.

**원고에 따라 개입 폭이 크게 다르다.** 학술문이나 보고문은 명사화 표현이 많아 고칠 부분이 많은 반면, 이미 자연스럽게 쓰인 구어체는 거의 그대로 둔다. 손을 대지 않는 결과도 정상이다.

## 이 문서도 이 도구로 다듬었다

README 본문을 `humanize.py`에 그대로 넣어 돌렸다. 대상 문단 26개, 변경률 4.6%였고 코드블록·표·링크·수치가 전부 그대로였다.

다만 **전부 반영하지는 않았다.** "다음은 그대로 통과한다"를 "해당 내용은 그대로 통과하며, 모델에 전달하지 않는다"로, "넣어두면 편하다"를 "등록해 두면 편리하다"로 바꾼 곳들은 오히려 딱딱해져서 되돌렸다. 여덟 군데다.

위의 «변경률은 품질 점수가 아니다»가 여기서 그대로 드러난다. 도구는 후보를 내놓고, 고를지는 사람이 정한다.
